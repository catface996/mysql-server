# 基于跳表实现的MySQL存储引擎设计

## 1. 概述

跳表(Skip List)是一种随机化的数据结构，基于并联的链表，实现简单，插入、删除、查找的时间复杂度均为O(log n)，是红黑树等平衡树的一个很好的替代品。本存储引擎基于跳表实现，旨在提供高效的数据存储和检索功能。

## 2. 核心数据结构

### 2.1 跳表节点结构
```cpp
struct SkipListNode {
    uchar* data;           // 行数据
    uint32_t data_length;  // 数据长度
    uint32_t level;        // 节点层级
    SkipListNode** forward; // 前向指针数组
};
```

### 2.2 跳表结构
```cpp
struct SkipList {
    SkipListNode* header;  // 头节点
    uint32_t level;        // 当前最大层级
    uint32_t size;         // 元素数量
    uint32_t max_level;    // 最大允许层级
};
```

### 2.3 表结构
```cpp
struct SkipTable {
    SkipList* primary_index;  // 主键索引
    std::map<uint, SkipList*> secondary_indexes;  // 二级索引
    char* table_name;         // 表名
    uint32_t row_count;       // 行数
    uint64_t data_size;       // 数据总大小
};
```

## 3. 存储引擎接口实现

### 3.1 MySQL必须实现的接口清单

以下是MySQL存储引擎必须实现的接口：

#### 基本操作接口（必须实现）
- `open()`: 打开表文件，加载表结构
- `close()`: 关闭表，保存表结构
- `rnd_init()`: 初始化表扫描
- `rnd_next()`: 获取下一行
- `rnd_pos()`: 根据位置获取行
- `position()`: 记录当前位置
- `info()`: 获取表信息
- `create()`: 创建表
- `store_lock()`: 存储锁

#### 元数据接口（必须实现）
- `table_type()`: 返回存储引擎类型名称
- `table_flags()`: 返回存储引擎支持的功能标志

#### 可选但推荐实现的接口
- `write_row()`: 写入行
- `update_row()`: 更新行
- `delete_row()`: 删除行
- `index_init()`: 初始化索引扫描
- `index_read_map()`: 索引读取
- `index_next()`: 获取下一个索引项
- `index_end()`: 结束索引扫描

### 3.2 基本操作接口

## 4. 存储格式

### 4.1 表文件格式
表数据存储在两个文件中：
- `.frm`: MySQL表定义文件（由MySQL自动管理）
- `.skl`: 跳表数据文件，包含表元数据和行数据

### 4.2 数据文件结构
```
[文件头]
- 魔数 (4字节)
- 版本号 (4字节)
- 表名长度 (4字节)
- 表名 (变长)
- 行数 (4字节)
- 数据总大小 (8字节)
- 主键索引偏移量 (8字节)
- 二级索引数量 (4字节)
- 二级索引偏移量列表 (每个8字节)

[主键索引]
- 节点数量 (4字节)
- 最大层级 (4字节)
- 节点列表 (变长)

[二级索引]
- 索引ID (4字节)
- 节点数量 (4字节)
- 最大层级 (4字节)
- 节点列表 (变长)

[数据区]
- 行数据 (变长)
```

## 5. 性能优化考虑

1. **内存管理**：实现自定义内存池，减少内存分配开销
2. **并发控制**：实现细粒度锁或无锁数据结构，提高并发性能
3. **持久化策略**：实现WAL(Write-Ahead Logging)，提高数据持久性和恢复能力
4. **缓存机制**：实现行缓存和索引缓存，减少磁盘I/O
5. **批量操作**：优化批量插入和更新操作
