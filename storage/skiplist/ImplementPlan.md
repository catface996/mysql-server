# 实现 MySQL SkipList 存储引擎的最小化版本与逐步完善计划

## 第一阶段：最小化存储引擎实现

### 步骤 1：简化数据结构
1. 保留基本的 SkipList 和 SkipTable 结构
2. 移除所有二级索引相关代码
3. 简化内存管理，使用 calloc 代替 malloc

### 步骤 2：实现最基本的存储引擎接口
1. 实现 create() - 只创建表结构，不保存
2. 实现 open() - 只加载表结构
3. 实现 close() - 释放资源
4. 实现 rnd_init(), rnd_next(), rnd_end() - 基本的表扫描

### 步骤 3：实现最基本的数据操作
1. 实现 write_row() - 只插入数据，不处理索引
2. 实现 delete_row() - 简单删除
3. 实现 update_row() - 简单更新

## 第二阶段：添加持久化功能

### 步骤 4：实现数据持久化
1. 实现 skiptable_save() - 保存表结构到文件
2. 实现 skiptable_load() - 从文件加载表结构
3. 修改 create() 和 close() 函数，添加持久化操作

### 步骤 5：实现事务日志
1. 添加简单的日志记录
2. 实现基本的崩溃恢复

## 第三阶段：添加索引功能

### 步骤 6：实现主键索引
1. 完善 skiplist_search() 函数
2. 实现 index_read_map() 函数
3. 实现 index_init() 和 index_end() 函数

### 步骤 7：实现二级索引
1. 添加二级索引支持
2. 实现二级索引的创建和维护
3. 实现通过二级索引的查询

## 第四阶段：优化和扩展

### 步骤 8：性能优化
1. 实现内存池，减少内存分配开销
2. 优化查询性能
3. 添加缓存机制

### 步骤 9：添加高级功能
1. 实现事务支持
2. 添加并发控制
3. 实现数据压缩

## 当前实现状态与下一步

目前，代码已经实现了基本的存储引擎框架，但在表创建时遇到了崩溃问题。建议先完成第一阶段的最小化实现：

1. 简化 `create()` 函数，只创建表结构，不保存
2. 简化 `open()` 函数，只加载表结构
3. 实现基本的 `write_row()` 函数，只插入数据
4. 实现基本的 `rnd_next()` 函数，只读取数据

这样可以先验证基本功能是否正常工作，然后再逐步添加更多功能。

每完成一个步骤，都应该进行测试，确保功能正常，然后再进行下一步。这种增量式的开发方法可以帮助更容易地定位和解决问题。
