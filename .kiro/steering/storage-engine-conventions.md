# 存储引擎工程规范和代码规范

基于InnoDB存储引擎的实现分析，以下规范适用于MySQL存储引擎的开发。

## 目录结构规范

### 模块化组织
存储引擎应按功能模块组织，每个模块有独立的目录：
- **`api/`** - 外部API接口
- **`buf/`** - 缓冲池管理
- **`dict/`** - 数据字典
- **`lock/`** - 锁管理
- **`log/`** - 日志系统
- **`page/`** - 页面管理
- **`row/`** - 行操作
- **`trx/`** - 事务管理
- **`handler/`** - MySQL接口层
- **`include/`** - 头文件

### 文件命名规范
- **源文件**: `模块名0子模块.cc`（如 `buf0buf.cc`、`dict0dict.cc`）
- **头文件**: `模块名0子模块.h`（如 `buf0buf.h`、`dict0dict.h`）
- **内联文件**: `模块名0子模块.ic`（如 `buf0buf.ic`）
- **数字0**: 用作模块名和子模块名的分隔符

## 命名规范

### 函数命名
- **模块前缀**: `模块名_子模块_功能名`
- **示例**: `buf_page_get()`, `dict_table_open()`, `lock_rec_lock()`
- **内部函数**: 可以省略子模块名，如 `buf_flush_page()`

### 类型命名
- **结构体**: `模块名_子模块_t`（如 `buf_page_t`, `dict_table_t`）
- **枚举**: `模块名_子模块_enum_t`
- **指针类型**: 通常直接使用结构体指针

### 常量命名
- **全大写**: `模块名_常量名`
- **示例**: `BUF_POOL_SIZE`, `DICT_MAX_FIELD_LEN`
- **使用constexpr**: 优先使用 `constexpr` 而非 `#define`

### 变量命名
- **局部变量**: `snake_case`
- **成员变量**: `snake_case`
- **全局变量**: 避免使用，如必须则加模块前缀

## 错误处理规范

### 错误码定义
```cpp
enum dberr_t {
  DB_SUCCESS = 10,
  DB_ERROR,
  DB_OUT_OF_MEMORY,
  DB_DEADLOCK,
  // ... 其他错误码
};
```

### 错误处理模式
- **返回错误码**: 函数返回 `dberr_t` 类型
- **断言检查**: 使用 `ut_a()` 进行运行时断言
- **调试断言**: 使用 `ut_ad()` 进行调试模式断言

## 内存管理规范

### 内存分配
- **使用内存堆**: `mem_heap_t` 用于临时内存分配
- **避免直接malloc**: 使用InnoDB的内存管理接口
- **RAII原则**: 使用智能指针或RAII包装器

### 缓冲区管理
- **页面缓冲**: 通过缓冲池管理页面
- **引用计数**: 正确管理页面引用计数
- **锁定机制**: 适当使用读写锁保护共享资源

## 并发控制规范

### 锁的层次结构
1. **表级锁**: 最高级别
2. **页面锁**: 中等级别
3. **记录锁**: 最低级别

### 锁定顺序
- **避免死锁**: 始终按固定顺序获取锁
- **最小锁定**: 只锁定必要的资源
- **及时释放**: 尽快释放不需要的锁

## 构建配置规范

### CMakeLists.txt结构
```cmake
# 版权声明

# 包含通用配置
INCLUDE(innodb.cmake)

# 编译选项
ADD_DEFINITIONS(-DLOG_SUBSYSTEM_TAG="存储引擎名")

# 源文件列表
SET(存储引擎_SOURCES
  模块1/文件1.cc
  模块2/文件2.cc
  # ...
)

# 创建库
ADD_LIBRARY(存储引擎 ${存储引擎_SOURCES})
```

### 编译标志
- **警告级别**: 启用高级别警告（`-W4` on MSVC, `-Wall -Wextra` on GCC）
- **调试信息**: 调试版本包含完整调试信息
- **优化**: 发布版本启用适当优化
