# 需求文档

## 介绍

本功能基于 SBT（Size Balanced Tree，尺寸平衡树）算法为 MySQL 实现一个简化的存储引擎。该存储引擎将遵循 MySQL 的存储引擎架构，提供基本的 CRUD 操作，不支持主键和索引。这是一个学习性实现，用于理解 MySQL 存储引擎接口和 SBT 数据结构。

## 需求

### 需求 1

**用户故事：** 作为数据库管理员，我希望能够使用 SBT 存储引擎创建表，以便使用 SBT 算法进行平衡树操作来存储数据。

#### 验收标准

1. 当 CREATE TABLE 语句指定 ENGINE=SBT 时，系统应当使用 SBT 存储引擎创建表
2. 当表创建时，系统应当初始化用于存储记录的 SBT 数据结构
3. 当表创建成功时，系统应当向客户端返回成功状态

### 需求 2

**用户故事：** 作为数据库用户，我希望能够向 SBT 表中插入记录，以便使用平衡树结构存储数据。

#### 验收标准

1. 当在 SBT 表上执行 INSERT 语句时，系统应当将记录添加到 SBT 数据结构中
2. 当插入记录时，系统应当维护 SBT 的平衡属性
3. 当插入操作完成时，系统应当返回受影响的行数
4. 当插入重复记录时，系统应当允许多个相同的记录（无唯一性约束）

### 需求 3

**用户故事：** 作为数据库用户，我希望能够从 SBT 表中查询记录，以便高效地检索存储的数据。

#### 验收标准

1. 当在 SBT 表上执行 SELECT 语句时，系统应当遍历 SBT 结构以查找匹配的记录
2. 当执行全表扫描时，系统应当返回表中的所有记录
3. 当应用 WHERE 条件时，系统应当根据指定条件过滤记录
4. 当没有记录匹配查询时，系统应当返回空结果集

### 需求 4

**用户故事：** 作为数据库用户，我希望能够更新 SBT 表中的记录，以便修改现有数据。

#### 验收标准

1. 当在 SBT 表上执行 UPDATE 语句时，系统应当定位并修改匹配的记录
2. 当更新记录时，系统应当维护 SBT 结构的完整性
3. 当更新操作完成时，系统应当返回受影响的行数
4. 当没有记录匹配更新条件时，系统应当返回零受影响行数

### 需求 5

**用户故事：** 作为数据库用户，我希望能够从 SBT 表中删除记录，以便移除不需要的数据。

#### 验收标准

1. 当在 SBT 表上执行 DELETE 语句时，系统应当从 SBT 结构中移除匹配的记录
2. 当删除记录时，系统应当根据需要重新平衡 SBT 树
3. 当删除操作完成时，系统应当返回受影响的行数
4. 当没有记录匹配删除条件时，系统应当返回零受影响行数

### 需求 6

**用户故事：** 作为数据库管理员，我希望 SBT 存储引擎能够与 MySQL 的处理器接口集成，以便与现有的 MySQL 基础设施无缝协作。

#### 验收标准

1. 当存储引擎加载时，系统应当将其注册到 MySQL 的插件系统中
2. 当 MySQL 启动时，系统应当正确初始化 SBT 存储引擎
3. 当 MySQL 关闭时，系统应当清理 SBT 存储引擎资源
4. 当使用标准 MySQL 命令时，系统应当与 SBT 引擎透明地工作

### 需求 7

**用户故事：** 作为数据库管理员，我希望 SBT 存储引擎能够将数据持久化到磁盘，以便数据在服务器重启后仍然存在。

#### 验收标准

1. 当插入或更新记录时，系统应当将更改写入磁盘存储
2. 当服务器重启时，系统应当从磁盘文件重新加载 SBT 数据
3. 当删除表时，系统应当移除相关的磁盘文件
4. 当发生磁盘 I/O 错误时，系统应当优雅地处理错误并报告适当的消息

### 需求 8

**用户故事：** 作为开发者，我希望 SBT 实现能够维护适当的树平衡，以便操作保持高效。

#### 验收标准

1. 当节点变得不平衡时，系统应当执行 SBT 旋转以恢复平衡
2. 当树大小改变时，系统应当维护每个节点的大小属性
3. 当执行树操作时，系统应当确保基本操作的 O(log n) 时间复杂度
4. 当发生树修改时，系统应当正确更新大小计数器
